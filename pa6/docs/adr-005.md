# ADR-005 — Sequential checkout with persistent replay and explicit compensation limits

**Status:** accepted
**Date:** 2026-10-22

## Context

The contract was written and linted before the saga code, in commit 9b44e0f. Spectral accepted it and rejected the supplied bad example with 13 errors, including an unbounded items array. This made the API limit explicit: 100 lines, enforced by validateCheckoutPayload rather than just documented. Shipping and notification offer no compensating endpoints, so rollback cannot mean erasing every external effect.

Verification observed an in-flight duplicate return 409, a shipping timeout return 504 with inventory_release then payment_refund, and replay after restart return the original response. In the separate crash experiment, killing the orchestrator after inventory left payment and inventory in the persisted trace and the key in_progress. Restarting and repeating the request returned 409 idempotency_conflict, rather than issuing another authorization.

## Decision

POST /checkout validates the unchanged canonical schema plus the contract's item and key bounds. payloadHash sorts object keys before SHA-256, so JSON property order does not create a false mismatch. saveRecord writes the initial in_progress guard synchronously before any downstream await. Each update reads the latest file, avoiding lost records when different keys execute concurrently. writeJsonFile uses temporary-file replacement so an interrupted write does not expose half-written JSON.

runSaga awaits payment, inventory, shipping and notification strictly in order. amountFor uses BigInt whole cents and formats once; customer.email supplies the recipient. callDownstream consumes each response within an AbortSignal timeout and records real timestamps. An aborted budget is timeout/504; a service refusal retains its machine code and maps to 422. Trace entries include compensation calls.

On failure, only confirmed completed steps are undone: inventory_release, then payment_refund. A failed release does not prevent trying the refund. Any compensation failure takes precedence as failed/422/compensation_failed. Shipping and notification are never given invented undo endpoints. A successful rollback reports compensated even though an external shipping effect might remain.

Completed, failed and compensated records persist their exact HTTP status and body. Same-key/same-payload requests replay that pair without another downstream call; changed payloads get idempotency_payload_mismatch. In-progress keys return idempotency_conflict, including after an interrupted process. The two store files are recovery evidence, not a distributed transaction.

## Alternatives considered

PA5 choreography suits independent reactions, but checkout needs a caller-visible ordering and one final result. Replacing this orchestrator with independent event consumers would require another coordinator to detect completion and arrange compensation. Parallel calls reduce latency but may ship an unpaid or unreserved order. Shipping cancellation could improve rollback, but the provider must implement it and define what happens once a package has left; adding a fake endpoint to the mock would hide this constraint.

Generating validation from OpenAPI could avoid schema drift. Here the course canonical schema remains authoritative, with only explicit API transport and item bounds added. Automatic startup replay of in-progress records was rejected: after a crash, an authorization may have succeeded without its response being saved. Blind replay risks another charge.

## Consequences

All 12 public tests and TypeScript checking passed. Extra checks covered 101-line rejection, property-order replay, compensation continuation and the mid-saga crash. The implementation, verification and ADR were prepared with AI assistance; no personal student authorship is claimed.

A killed saga can remain guarded forever without operator reconciliation; PA7 addresses durable continuation. Two replicas cannot safely coordinate these JSON files, and two distinct keys for one orderId can both execute and overwrite that order's debug record. A fifth step needs its request, trace name, compensation position and contract bounds updated. Timing out a call does not prove the provider cancelled its side effect. File replacement is not a transaction across both files or the services. These are accepted limits of a single-process exercise, not an exactly-once checkout guarantee.

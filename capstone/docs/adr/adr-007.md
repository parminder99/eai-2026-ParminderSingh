# ADR-007: Event-started saga and acknowledgement ordering

Status: accepted

## Context
HTTP acceptance and distributed completion have different lifetimes. An HTTP timeout must not hold a checkout open.

## Decision
Publish canonical orders with broker confirms; persist saga intent before provider calls, store terminal outcomes before publishing them, and acknowledge only after the outcome confirm. Redelivery republishes stored terminal outcomes. Prefetch five permits unrelated orders to progress while per-correlation tasks serialize duplicates. Intake follows a separate durable lifecycle queue and does not regress terminal status.

## Alternatives considered
Synchronous checkout couples acceptance to every provider. Acknowledging before persistence loses work. A transactional outbox would close publish/store gaps but adds a separate dispatcher.

## Consequences
The store and broker are not one transaction: acceptance can be ambiguous on a crash. Stable business keys and terminal outcome republishing repair duplicates, while interrupted hand-rolled work requires review.

# ADR-011: Temporal owns durable workflow scheduling

Status: accepted

## Context
The hand-rolled journal intentionally cannot safely resume every uncertain execution point.

## Decision
Start one workflow per source:orderId on task queue checkout. The deterministic workflow stores its completed-step list through history. Activities own HTTP I/O, retry temporary failures up to three attempts, and make permanent 4xx failures non-retryable. Compensation executes in reverse order.

## Alternatives considered
Reimplementing a workflow engine would add timers, durable queues and replay logic. Putting HTTP calls in workflow code breaks deterministic replay.

## Consequences
Worker restarts replay workflow history rather than rerunning completed activities. Provider keys still protect activity retries; Temporal does not make external effects transactional. Activities mirror diagnostic state to the orchestrator before publishing outcomes.

## What the engine took over
- Durable scheduling and resumption from workflow history.
- Activity retry timers and timeout bookkeeping.
- Workflow identity and duplicate-start rejection.
- Persisting the compensation order through deterministic replay.
